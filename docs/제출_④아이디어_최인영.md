## [활동 5] 개방 CSV 인코딩 비일관 — 직접 개선 수행

| 칸 | 작성 내용 |
| --- | --- |
| **활동유형** | ☑ 공공데이터 개선·활용 아이디어 |
| **대상 데이터/서비스** | 한국석유공사 개방 CSV 73개 전체 |
| **점검·활동 내용** | 개방 CSV 73개의 인코딩을 전수 판별하고, CP949 파일을 UTF-8(BOM)로 변환한 뒤 원본과 대조해 데이터 손실 여부를 검증함 |
| **발견사항 / 현황** | 개방 CSV 73개 중 CP949가 67개, UTF-8(BOM)이 6개로 인코딩이 두 가지로 갈려 있다. 동일 기관이 동일 포털을 통해 개방한 파일인데 기준이 통일되어 있지 않다. |
| **개선대상 / 문제점** | CP949 파일은 UTF-8을 기본값으로 사용하는 환경(맥·리눅스 및 대부분의 데이터 분석 도구)에서 한글이 깨진다. 반대로 BOM이 없는 UTF-8은 엑셀이 CP949로 오독해 역시 깨진다. 73개를 일괄 처리하려면 파일별 인코딩 판별 로직을 먼저 작성해야 하며, 프로그래밍에 익숙하지 않은 이용자는 파일을 연 시점에 활용을 포기하게 된다. |

**1. 활동 10의 유형 중복 확인** — 오피넷 API 가이드 불일치는 성격상 ① 개방데이터 오류 점검에 가깝다.

# 종합 의견 재료 (④ 관점 — 취합 담당 참고용)

팀 종합 의견은 취합 담당이 ①②와 함께 작성한다. ④에서 나온 재료는 다음과 같다.

- **우선 개선 대상**: 가격데이터 시계열 미제공(활동 1), 주유소 고유 식별자 부재(활동 2).
  둘 다 개별 오류가 아니라 활용 가능성을 제약하는 구조적 요인이며, 같은 기관이 이미
  요소수 51개월·비축일수 22년 시계열을 제공하고 전국 개별 주유소 파일이 고유 식별자를
  쓰고 있으므로 기존 방식을 다른 파일로 확대 적용하는 수준에서 해결 가능하다.
- **시사점**: ① 개방의 양보다 결합 가능성이 활용을 좌우한다(인천 79.2%, 알뜰 92.0%).
  ② 같은 기관 안에서 기준이 통일되지 않은 사례가 반복된다(인코딩·상표명칭·기간표기·단위).
  ③ 목록 단위와 파일 단위의 불일치가 실제 집계 오류를 일으킨다(86개 → 실제 84건).
  ④ 파일을 직접 열어보기 전에는 드러나지 않는 문제가 있다(가격 파일이 1~2행 스냅샷).
